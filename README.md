# Paste into all — VSIX для Visual Studio (C#)

Расширение для Visual Studio, которое вставляет выделенный код туда, где вы сейчас работаете: по умолчанию в чат **OpenCode**, но целевое приложение настраивается — VS Code, браузер, терминал, блокнот и любое другое окно.

Проверено на практике: браузеры (Chrome/Edge), OpenCode, VS Code и Блокнот.

> Важно: приложение, указанное в настройке **Target application**, должно быть **уже открыто** — расширение не запускает ничего, кроме OpenCode. Если окна нет, код остаётся в буфере обмена, а расширение предлагает нажать `Ctrl+V` вручную.

Как это работает:

1. Выделяете фрагмент кода в редакторе Visual Studio.
2. Нажимаете **`Ctrl+Alt+Shift+O`** (или пункт меню `Tools → Paste into all`, или правый клик в редакторе → `Paste into all` — сочетание клавиш показано справа и в меню «Средства», и в контекстном меню).
3. Код копируется в буфер обмена.
4. Окно целевого приложения выводится на передний план и в него отправляется `Ctrl+V` — код оказывается в поле ввода.

Если вместо OpenCode нужно вставлять в другое приложение, укажите его в настройке **Target application** (имя процесса или часть заголовка окна): например `Code`, `chrome`, `notepad`. Автозапуск при этом не выполняется — приложение должно быть уже открыто.

Если выделен **весь файл** (или выделения нет — тогда файл берётся целиком), вставляется **только полный путь к файлу**:

```
D:\Projects\App\Services\UserService.cs
```

Так чат получает ссылку на файл, а не его содержимое. При желании можно включить в настройках добавление кода после пути.

Если выделен только фрагмент, вставляется только сам фрагмент, без пути.

Если OpenCode **закрыт**, расширение запускает его автоматически, ждёт появления окна и вставляет текст в чат — в Visual Studio текст не попадает никогда. Для любого другого целевого приложения автозапуска нет: его нужно открыть заранее.

## Локализация

Команда называется **Paste into all** в английской Visual Studio и **Вставить в приложение** в русской. Это не переопределение заголовка в рантайме (через `OleMenuCommand.Text` оно не работает), а штатный механизм VSCT: две таблицы команд компилируются в `Menus.ctmenu`, вливаются в культуро-зависимые ресурсы (`MergeWithCTO`) и попадают в сателлиты `en-US\` и `ru-RU\PasteIntoAll.resources.dll`.

Важные детали, без которых меню пропадает или остаётся английским:

- В основной сборке обязателен **нейтральный** набор ресурсов (`Resources.resx` без `MergeWithCTO`). Без него Visual Studio не находит `Menus.ctmenu` и команда исчезает целиком (например, в русской VS).
- `LogicalName` у культуро-зависимых ресурсов должен быть уникальным, иначе MSBuild падает с `MSB3577` (два выхода в один файл).
- Нейтральный и культуро-зависимый VSCT не могут сосуществовать: `VSSDK1006: Two cto files have the same resource name 'Menus.ctmenu'`. Поэтому оба VSCT только с культурой в имени.
- Горячая клавиша из сателлита не регистрируется, поэтому пакет при старте проверяет привязку и при необходимости назначает её через `EnvDTE`.
- Пункт контекстного меню — это та же команда, размещённая через `<CommandPlacements>`: так Visual Studio сама показывает `Ctrl+Alt+Shift+O` справа и в «Средствах», и в меню по правому клику, без дублирования команды и второй горячей клавиши.
- Каноническое имя команды в DTE зависит от языка (`Tools.Вставитьвприложение`), поэтому поиск идёт по GUID и ID команды.
- DTE разбирает клавишу привязки через активную раскладку: при русской раскладке `Ctrl+Alt+Shift+O` превращается в `Ctrl+Shift+Alt+·`. Пакет переводит `O` в символ текущей раскладки (`ToUnicodeEx`), VS сохраняет и показывает `Ctrl+Shift+Alt+O`.

Карточка расширения в диспетчере расширений локализуется через `ru-RU\Extension.vsixlangpack`.

Страница настроек тоже переведена: у VS нет штатного атрибута для локализации `DisplayName`/`Description`/`Category` в `DialogPage`, поэтому `PasteIntoAllOptionsPage` реализует `ICustomTypeDescriptor` и подменяет `PropertyDescriptor`-ы. Строки лежат в `Localization.cs` и выбираются по `CultureInfo.CurrentUICulture` (`ru` → русский, остальные → английский). Названия самой страницы (`General`) и категории (`Paste into all`) VS берёт из pkgdef и не локализует — для этого нужен Win32-ресурс в native-сателлите, которого у managed-VSIX нет.

## Сборка

Нужен MSBuild из Visual Studio (не `dotnet build`) — VSIX-у нужны задачи VSSDK.

```powershell
.\build.ps1
```

или вручную:

```powershell
& "C:\Program Files\Microsoft Visual Studio\18\Insiders\MSBuild\Current\Bin\MSBuild.exe" `
    "PasteIntoAll.sln" -restore -p:Configuration=Release
```

Результат: `src\PasteIntoAll\bin\Release\net472\PasteIntoAll.vsix`.

## Установка

Официальный способ (Visual Studio должна быть закрыта):

```powershell
& "C:\Program Files\Microsoft Visual Studio\18\Insiders\Common7\IDE\VSIXInstaller.exe" `
    "src\PasteIntoAll\bin\Release\net472\PasteIntoAll.vsix"
```

После установки (или после копирования файлов расширения) нужно **перезапустить Visual Studio**.

## Настройки

`Tools → Options → Paste into all → General`:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| Paste delay (ms) | 350 | Пауза после активации целевого окна перед `Ctrl+V`. Увеличьте, если текст иногда не вставляется. |
| Start OpenCode when it is not running | включено | Если окно OpenCode не найдено, запустить приложение, дождаться окна и вставить текст туда. |
| Startup timeout (seconds) | 30 | Сколько ждать появления окна после запуска OpenCode. |
| OpenCode executable path | пусто | Путь к `OpenCode.exe`. Пусто — автопоиск: `Programs\ai.opencode.desktop`, App Paths, ярлык в меню «Пуск», запись деинсталляции. |
| Target application (process or window title) | `opencode` | **Целевое приложение**: имя процесса (`opencode`, `chrome`, `Code`, `notepad`) или фрагмент заголовка окна. Приложение должно быть уже открыто. Пусто или `opencode` — вставлять в OpenCode. |
| Send the full file path when the whole file is selected | включено | При выделении всего файла отправлять путь вместо кода. |
| Also append the file contents for a whole file | выключено | Дополнительно дописать код после пути. |
| Treat an empty selection as the whole file | включено | Если ничего не выделено — считать, что выбран весь файл. |

Настройки переведены: в русской Visual Studio названия параметров и подсказки к ним показываются по-русски (группы «Вставка» и «Содержимое»).

## Как ищется целевое окно

По умолчанию (настройка пуста или содержит `opencode`):

1. Сначала ищется видимое окно процесса `OpenCode` (приложение OpenCode Desktop). Из нескольких окон берётся то, что выше по Z-порядку.
2. Затем — любое окно, в имени процесса которого есть `opencode`.
3. Затем — окно терминала, в заголовке которого есть строка из настройки.

Любое другое значение настройки ищется так:

1. Точное совпадение имени процесса (`chrome`, `notepad`, `Code`).
2. Имя процесса частично: `code` найдёт `Code` и `VSCode`.
3. Заголовок окна без учёта регистра и пробелов: `vscode` находит «Visual Studio Code», `visualstudiocode` — тоже.

Окно самой Visual Studio (процесс, в котором работает расширение) не используется никогда. Перед отправкой `Ctrl+V` проверяется, что на переднем плане именно найденное окно, поэтому текст не попадёт в случайное приложение.

Если окно так и не появилось, код остаётся в буфере обмена — можно переключиться в приложение и нажать `Ctrl+V` вручную.

## Замечания

- Горячая клавиша по умолчанию: `Ctrl+Alt+Shift+O` (меняется в `Tools → Options → Environment → Keyboard`, команда `Tools.PasteIntoAll`). Комбинация `Ctrl+Alt+O` в Visual Studio уже занята командой `View.Output`, поэтому выбрана свободная.
- Если VSCT-привязка не применилась или в настройках осталась «битая» привязка (например, с не-ASCII именем клавиши после смены раскладки), пакет при загрузке сам назначает `Ctrl+Alt+Shift+O` через модель автоматизации. Имя области берётся из существующих команд шелла, потому что в русской VS это не `Global`, а `Везде`.
- Текст вставляется «как есть», без обрамления в markdown-блок; завершающие переводы строки обрезаются, чтобы чат не отправил сообщение сразу.
- Диагностика пишется в `%TEMP%\paste-into-all.log`: инициализация горячей клавиши и результат каждой отправки (запуск, найдено окно, активация, вставка).
- Расширение написано против VS SDK 17.14 (сборки совместимы с Visual Studio 2026), манифест при этом разрешает установку в VS 2026 (`[18.0,19.0)`).
